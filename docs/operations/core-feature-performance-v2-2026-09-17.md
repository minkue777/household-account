# 핵심 기능 성능 기준 강화와 통계 전환 개선

이전 비교 대상은 [1차 최적화 측정](core-feature-performance-gates-2026-09-17.md)입니다. 기존 보고서의 v1 기준과 원본을 보존하고 이번 v2 측정을 별도로 기록합니다.

## 목표와 변경

| 기능 | 중앙값: 이전 → v2 | 7회 중 6회: 이전 → v2 | 개별 최대: 이전 → v2 |
|---|---:|---:|---:|
| 첫 검색 입력·검색창 열기 → 결과 | 1500 → 500ms | 2500 → 800ms | 5000 → 1500ms |
| 지출·자산 통계 첫 진입 | 2000 → 800ms | 3000 → 1200ms | 5000 → 2000ms |
| 통계 기간 변경·재진입 | 1500 → 400ms | 2000 → 600ms | 5000 → 1200ms |

나머지 홈·자산 목록·편집·Android Native 기준은 유지합니다. CI의 기존 WebKit/Native 환경별 고정 허용값도 유지하지만 검색·통계에는 새 사용 목표를 그대로 적용합니다. 정책과 프로필 이름은 v2로 구분합니다.

- 실제 제품의 지출·자산 통계 차트 5개가 공용 motion hook을 사용합니다. Chart.js 기본 1000ms 전환을 150ms로 줄이고, OS의 동작 줄이기 설정에는 애니메이션을 끕니다. hover 전환도 같은 정책입니다. 부모 조회 상태만 바뀔 때 options 안정성은 유지합니다.
- 지출 통계의 단발 조회를 기존 Firestore Lite 읽기 경계로 옮겼습니다. 서버 범위·cursor·전체 페이지 완료·50000건 상한·세션 폐기·60초 캐시·재진입 서버 재검증은 유지합니다. 실시간 원장 구독과 Firebase 배포 구성은 바꾸지 않습니다.
- 공용 optimistic projection에 저장 중인 변경이 없을 때는 해당 조회 구독만 갱신합니다. 검색 결과 발행·종료로 변경 없는 배경 원장까지 다시 그리던 동작을 줄였습니다. 저장 중에는 기존 구독 간 보정 동작을 유지합니다. 검색 결과 월별 그룹도 원본·합계가 바뀔 때만 계산합니다.
- 차트 시간 감소와 서버 조회 시간 감소를 합친 화면 완료 지표입니다. 감소분 전체를 데이터베이스 성능 개선으로 해석하지 않습니다. 테스트 전용 애니메이션 설정이나 완료 시점 앞당기기는 없습니다.
