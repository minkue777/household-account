# 카테고리 터치 순서 변경

## 원인

- 설정 목록이 HTML `draggable`·`dragstart`·`drop`만 사용했다. 휴대폰 터치 입력 처리와 손잡이가 없어 사용자가 끌어도 순서를 바꾸지 못했다.
- 순서·기본 카테고리 명령은 로그인 때 읽은 `household.categoryCatalogVersion`을 재사용했다. 카테고리 추가·수정·첫 정렬 이후 서버 버전은 증가하지만 해당 값은 갱신되지 않아 후속 변경이 충돌할 수 있었다.

## 수정

- 기존 색상 원의 카테고리 글자와 크기를 유지하면서 Pointer Events로 터치·마우스 입력을 통합했다. 색상 원에만 `touch-action: none`을 적용하여 이 부분을 잡아 순서를 바꾸고 목록의 다른 부분에서는 평소처럼 스크롤한다. 첫 수정의 점 6개 아이콘은 사용자 요청에 따라 제거했다.
- 드래그 중 항목 이동과 대상 표시, 화면 가장자리 스크롤을 제공한다. 놓을 때 한 번 저장하며 취소는 저장하지 않는다. 키보드 위·아래 방향키도 같은 저장 경로를 사용한다.
- 설정 섹션을 펼친 동안 기존 `categorySettings/default` 한 문서에서 권위 카탈로그 버전과 기본 카테고리를 구독한다. 명령 성공 후 구독 갱신을 확인한 다음 후속 변경을 허용한다. archive는 준비·완료 두 트랜잭션을 기다린다. 전체 카테고리 재조회나 자동 재시도는 추가하지 않았다.
- 정렬에는 활성 항목만 포함한다. 기존 색상 16개와 입력 너비·팝업 잘림 수정은 유지한다.

## 검증 범위

- 컴포넌트 검사: 터치 이동·취소, 한 번 저장, 중복 제출 방지, 실패 안내, 응답보다 늦은 버전 갱신과 연속 저장.
- 모바일 Chromium E2E: 테스트용 Firebase Emulator 가구에서 브라우저의 실제 touch 입력을 전달하고 서버 원본·Web 조회 문서·새로고침 순서를 비교한다. 실제 Android 단말 WebView 및 iPhone에서의 직접 확인과는 구분한다.
- 운영 가계부의 카테고리 순서를 시험 목적으로 변경하지 않는다.

로컬 최종 검증은 Functions 품질 게이트(2,839개 및 architecture 38개), Web 627개, 실제 모바일 터치를 포함한 Emulator E2E 1개, 프로덕션 빌드·PWA E2E 2개 모두 통과했다. 모바일 E2E에서 순서 변경 두 번의 서버 저장과 새로고침 유지를 확인했다.
