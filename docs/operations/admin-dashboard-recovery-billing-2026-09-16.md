# 관리자 장애 복구와 비용 상세 (2026-09-16)

- 실제 운영에서 9월 10일 01:00 KST에 열린 asset-automation-daily MISSING 장애가 이후 정상 완료에도 OPEN 상태로 남았다. 감시 대상이 최근 48시간으로 제한됐고 같은 occurrence 종료만 복구로 처리했다.
- 예약 실행 완료 transaction에서 해당 실행의 지연 경보 및 같은 작업의 이전 경보를 닫는다. 다음 실행에 의한 복구는 COMPLETE일 때만 인정한다. 다른 작업의 성공이나 PARTIAL_FAILURE는 복구 증거가 아니다. 기존 실패 실행은 변경하지 않는다.
- monitor는 오래된 OPEN 장애도 검사한다. 대시보드 조회는 이미 저장된 성공 실행으로 복구를 판정하므로 다음 monitor를 기다리지 않는다. 열린 장애가 있는 화면은 10초 간격, 나머지는 기존 60초 간격이며 탭 복귀 시 갱신한다. 최근 24시간의 처리 시간·실패 통계는 과거 사실이므로 삭제하지 않는다.
- Cloud Billing standard export의 SKU·리전·pricing unit별 사용량, 사용 비용, 크레딧, 순비용을 월 단위로 집계한다. 같은 원천 필터를 사용하고 credits를 펼쳐 사용량을 중복 합산하지 않는다. 0원인 사용 항목과 소수 원 단위 비용도 상세에 유지한다.
- 실제 App Engine 청구 항목은 Firestore 조회, 쓰기, 일반 삭제, TTL 삭제, 저장 공간, 외부 전송이었다. 기존 서비스 합계만으로는 원인을 알 수 없었다. 상세 UI는 App Engine 항목을 기본으로 펼치고 실제 SKU 이름도 병기한다. 화면별·함수별 비용으로 추정 배분하지 않는다.
- skuAmounts는 admin-access-response.v1의 선택적 응답 필드다. 기존 스냅샷·기존 서버는 서비스 합계를 계속 표시하고 상세 준비 문구를 표시한다. 요청·권한·기존 필드는 변경하지 않는다.
- 검증: 예약 저장소 실제 completion/monitor 경로의 장기 장애 복구·다른 작업·부분 실패·중복 관측 회귀 검사, BigQuery adapter와 비용 요약 검사, 관리자 렌더링 및 실제 emulator callable→화면 E2E에 비용 상세와 복구 전후 전환을 추가한다.
