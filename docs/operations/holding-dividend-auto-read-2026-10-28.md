# 주식계좌 배당 자동 표시

## 원인

주식계좌 목록의 배당 조회가 `StockHoldingList.handleOpenHolding`에만 연결되어 있었다. 계좌 진입에서는 조회하지 않고 종목 편집을 열어야 요청하므로, 편집을 닫은 뒤에야 최근 지급액과 지급일이 표시됐다. 이 동작은 2026-07-23의 `02376f8e` 상호작용 지연 최적화에서 도입됐으며 기존 `HOLD-005`와 UI 테스트도 선택한 종목만 조회하도록 명시했다. 배당 수집·계산 누락과는 별개인 화면의 조회 시점 문제다.

## 변경 계약

- 기존 가구 Position snapshot으로 계좌 목록을 즉시 표시한다. 새 보유 listener나 시세 갱신을 추가하지 않는다.
- 계좌가 열리면 배당 지원 코드의 가구 Projection을 자동으로 조회한다. 각 응답이 도착할 때 최근 배당·지급일을 표시하고 다른 종목의 응답을 기다리지 않는다.
- 정렬된 고유 코드 집합을 조회 기준으로 사용한다. 중복 보유, 배열 순서·시세·수량·편집 변경은 재요청을 만들지 않는다. 보유 목록이 늦게 도착하거나 코드 집합이 변경되면 자동 조회한다.
- 계좌 전환·닫기 이후 이전 응답은 버린다. 다시 열 때 최신 Projection을 읽으며 실패한 조회도 재시도한다.
- 실패한 종목에는 조회 실패를 표시하고 다른 종목의 성공 결과는 그대로 보여준다. 배당 기록이 없는 정상 응답과 실패를 구분한다.
- 서버 권한·계산·저장 정책은 변경하지 않는다. Web 실행 코드만 변경하므로 Vercel Git 자동배포 대상이며 Firebase·APK 재배포는 필요 없다.

## 검증

- Jest: 클릭 없는 자동 조회, 응답 전 목록 표시, 동일 코드 중복 제거, 시세·편집 변경 시 조회 유지, 늦은 목록, 비지원 종목 제외, 개별 실패 분리, 계좌 전환 응답 폐기, 재진입 최신 조회.
- Playwright `holding-dividends.spec.ts`: 실제 Auth·Functions·Firestore Emulator와 production Web build를 사용한다. 실제 가구 배당 Query 응답 전달만 보류하여 목록 선표시를 확인하고, 응답 후 클릭 없는 배당·지급일 표시 및 재진입 갱신을 확인한다. 운영 데이터는 사용하거나 변경하지 않는다.
- 요구사항 `HOLD-005`·`T-PERF-HOLD-001`, 아키텍처 설명, E2E 추적성을 새 동작으로 갱신한다.
