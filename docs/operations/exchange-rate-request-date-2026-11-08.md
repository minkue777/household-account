# USD/KRW 환율 조회 기준일 고정

## 관측과 원인

2026-11-08 운영 읽기 전용 조사에서 Frankfurter `exchange-rate`가 11월 6일 22:18:11부터 11월 7일 23:55:04까지 한국시간 기준 5회 연속 `CONTRACT_FAILURE / INVALID_EXCHANGE_RATE_DATE`로 기록된 것을 확인했다. 이 코드는 정상 JSON의 고시일이 조회 당시 서울 날짜보다 미래일 때 발생한다. 당시 공급자 응답 원문은 보존하지 않으므로 실제 반환 날짜와 공급자 내부 원인은 미확정이다.

마지막 저장된 성공 관측은 `rateDate=2026-11-06`, `rate=1342.15`, `observedAt=2026-11-06T01:20:48.486Z`였다. 실패 시 미국 주식 평가는 이 관측을 유지한다. 11월 8일 직접 공개 API GET에서는 날짜 없는 조회와 `date=2026-11-08` 조회 모두 HTTP 200, 고시일 11월 8일로 응답했다. 이것은 현재 조회 성공이며 과거 실패가 없었다거나 운영 Health가 복구됐다는 뜻은 아니다.

## 변경 계약

- 기존 Frankfurter v2 USD/KRW 공급자를 유지하고 요청 시작의 서울 날짜를 `date` query로 명시한다. 공급자 선택이나 환산 기준은 바꾸지 않는다.
- 응답 고시일 상한도 같은 요청일로 고정한다. 응답 중 자정이 지나도 요청일 이후 날짜는 거부하며 주말·휴일의 직전 고시일은 허용한다.
- 미래·잘못된 응답의 거부, 최신 성공 관측의 독립 저장·보존, 5분 HTTP 캐시와 동시 요청 공유, provider Health 실패 기록은 유지한다.
- JPY 결제 환율은 이미 결제일을 명시하므로 변경하지 않는다. 과거 거래·운영 자산·Health 문서의 직접 수정은 하지 않는다.

공식 API의 날짜 지정 단일 통화쌍 조회: <https://frankfurter.dev/#rate>.

## 검증과 배포 범위

실제 시장 데이터 Adapter를 통한 서울 자정 전후·주말 날짜 지정, 직전 고시일 적용, 응답 중 자정 통과 시 미래 환율 거부와 기존 성공 관측 보존을 추가 검증했다. 시세 Adapter·동시성·갱신 정책 3파일 58검사가 통과했다.

Functions 공용 코드 변경이므로 Firebase 세 codebase 배포 대상이다. Web·APK 변경은 없다. 기본 배포 smoke와 전체 원격 CI는 별도로 확인하며, 운영 Health 복구는 배포 후 실제 정상 자산 갱신 결과가 있어야 판정한다.
