# 경기지역화폐 결제 취소 누락 수정

## 확인된 문제와 범위

2026-09-29 경기지역화폐의 `결제 취소 4,000원`·`결제 취소 7,000원` 알림은
서버에 도착했지만 잔액만 파싱됐습니다. 운영 receipt는 거래 `absent`, 잔액
`updated`로 완료됐고 두 승인 원장이 active 상태로 남았습니다.
같은 가맹점의 최종 3,500원 결제는 정상입니다.

검증된 경기지역화폐 취소 형식을 서버 parser에서 지원하고 기존 Capture 취소 경계로
전달합니다. 대전·세종의 미확인 취소 형식은 이번 지원 범위에 포함하지 않습니다.
Android APK는 원문을 전달하므로 변경하지 않습니다.

## 요구사항·상세 설계·계약

- `PARSE-GYEONGGI-001` / `T-PARSE-002`: 독립 행 `결제 취소 N원`을 양의 정수
  cancellation으로 해석합니다. 금액은 기존 상한을 유지하고 0·음수·소수·범위 초과,
  취소 신청/실패/안내 문구는 거래로 만들지 않습니다. 잘못된 취소 행은 승인으로
  fallback하지 않으며 유효한 잔액은 독립 보존합니다.
- 기존 결제 완료·잔액 전용·서울 게시 시각·가맹점 추출 계약을 유지합니다.
  경기 parser는 1.1.0, 이를 재사용하는 SMS parser는 1.3.0으로 표시하며 구버전
  envelope의 허용 출처·카드·지역화폐 검증을 유지합니다.
- `CAN-003` / `CAN-007`: 원 금액·원 가맹점·카드 증거가 일치하는 유일한 승인
  lineage만 기존 취소 로직으로 제거합니다. 별도 금액 승인과 재전송 멱등성을 보존합니다.
- `ING-008` / `BAL-003`: 취소 거래와 잔액 분기를 독립 처리하고 오래된 알림을
  복구할 때 최신 잔액을 덮어쓰지 않습니다. 공개 wire 스키마는 변경하지 않습니다.

## 기존 두 건 복구

사용자가 확인된 두 건의 취소 반영을 승인했습니다. 운영 원문·승인 증거·현재 원장의
금액/가맹점/lineage를 재확인하고 30일 내 후보를 먼저 검사합니다.
기존 balance-only receipt를 수정하거나 동일 observation으로 덮어쓰지 않습니다.
동일 금액의 과거 승인이 여러 건이면 자동 후보 선택을 우회하거나 규칙을 완화하지 않습니다.
사용자가 승인한 날짜·원장 ID에 해당하는 계보를 명시적으로 지정하고, 별도의 고정 복구
키와 현재 version으로 기존 `cancelCapturedLineage` 서비스를 통해 원자적으로 처리합니다.
처리 결과와 기존 receipt를 보존합니다. 현재 잔액과 정상 3,500원 거래가 동일한지
사후 검증합니다. 원문·사용자 식별자·토큰은 이 문서와 Git에 저장하지 않습니다.
