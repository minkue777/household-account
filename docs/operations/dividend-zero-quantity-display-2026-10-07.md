# 배당 상세의 0주 항목 제외

## 요청과 원인

월별 배당 상세에 배당 기준 수량 0주·금액 0원인 항목이 표시됐다. 서버는 유효한 0주 근거를 가진 확정·지급 이벤트도 보존하며, 기존 화면은 이벤트의 지급 연월만 필터링했다. 예상 배당은 이미 현재 수량이 양수일 때만 생성하므로 확정 상세의 표시 조건이 빠진 문제다.

운영 읽기 조사에서는 공시 이벤트 생성 이후 두 원천 Position을 삭제한 기록과, 그 삭제로 생성된 0주 history를 최근접 근거로 사용한 이벤트가 확인됐다. 기준일 당일 이력은 없었다. 완료된 최초 이관 계획에는 양의 수량이 있었으나 일반 history가 존재하면 이관 근거를 보충하지 않는 현재 Query 계약에 따라 삭제 history만 선택됐다. 가계부 삭제 시각은 실제 매도일의 증거가 아니며, 표시 필터로 기준일 수량 계산의 정확성이 해결됐다고 보지 않는다. 기존 최근접 복구 정책·paid 불변·운영 데이터는 이번 표시 변경 대상이 아니다. 운영 원문과 식별자는 저장소 밖 TEMP의 진단 파일에만 보관한다.

## 계약과 구현

- `DIV-001`: 월 상세에서 지급 연월에 해당하고 저장된 배당 기준 수량이 양수인 이벤트만 표시한다.
- 현재 보유 없음·전량 매도 여부로 과거의 양수 배당을 숨기지 않는다.
- 양의 소수 수량은 반올림한 금액이 0원이어도 표시한다. 금액 필터로 대체하지 않는다.
- 원천 Event·Projection과 월/연간 합계는 그대로 둔다. UI는 조회 실패를 빈 성공으로 처리하지 않는다.
- `AssetDividendChart.selectedMonthEvents`의 기존 조건에 `event.quantity > 0`만 추가한다. 상태·조회·서버 계층을 추가하지 않는다.

## 검증과 배포

- `assetDividendChartIdentity.contract.test.tsx`: 0주 제외, 현재 보유 없는 과거 배당·소수 수량 보존, 상세·차트 합계·원본 보존. 수정 전 신규 회귀 실패를 확인했다.
- `portfolio-reporting.spec.ts`의 `T-DIV-004/007`: 실제 Emulator Scheduler가 0주/양수 이벤트를 paid·Projection으로 보존한 뒤 SDK 조회와 실제 차트 클릭을 거쳐 0주만 숨기는지 검증한다. 현재 원천 자산이 없어도 양수 배당 표시, 합계·Projection 무변경, 직접 쓰기 거부·멱등성·과거 연도 조회 검사는 유지한다.
- Web Git 자동배포 대상이며 Firebase·APK 실행 코드는 변경하지 않는다.

수정 전 새 회귀 1개가 실패했고, 수정 후 관련 Jest 2파일 14개와 Web 타입 검사가 통과했다. 실제 Auth/Functions/Firestore Emulator·production Web build·Chromium 검사는 1개가 통과했다(42.2초). 실제 예약 실행이 0주 원천을 보존한 상태에서 양수 막대를 클릭해 상세에서 0주 제외·과거 10주 표시·1,200원 합계·Projection 무변경을 확인했다. E2E 준비의 architecture 43개, 요구사항 선언 검사 2개, 문서 링크 검사 1개, catalog·E2E 추적성(누락 0개)도 통과했다. 에뮬레이터는 정상 종료했다. 로그는 `TEMP/household-zero-dividend-{before,unit,types,prepare,e2e,docs}-20261007.log`에 둔다.
